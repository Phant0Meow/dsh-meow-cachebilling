# meow-cachebilling

DeepSeek Harness (DSH) 缓存账单插件：在输入框下方的统计条旁，实时显示**当前这一轮**请求里，缓存命中、未命中输入、输出各花了多少钱，以及本轮总价。

## 为什么会有这个插件

DeepSeek 的缓存命中率很高，大家会下意识觉得缓存命中率越高越好。但其实不是这样的。

在 Harness 不会破坏前缀的前提下（同一个 Harness 内对话前缀总是稳定复用），缓存命中率如果是 100%，其实可能反而是浪费钱的——它意味着你的上下文从来没有被精简过，每一轮都在为整个膨胀的前缀付费。

DeepSeek 的缓存命中特别便宜（未命中的 1/30），所以这笔钱总是容易被人忽略。但在上下文特别长的时候，缓存的价格其实也是惊人的。

这个插件专门算出你每轮为缓存花的钱。当轮次数越来越多的时候，你会看到每轮的缓存消耗逐渐变多——看到每轮到底是多少，大概能够指导我们选择更好的时机换窗口。

在我的实际测试中发现，当换窗口的时机更科学的时候，每日做同样的任务量，花费实际上能下降不少。

## 功能

- **四项实时读数**（输入框下方统计条旁）：`本轮 ¥0.0219｜缓存 0.0015 · 未命中 0.0198 · 输出 0.0006`
- **一轮 = 每次大模型 API 请求**：AI 中途调用工具后再请求 API 也算新一轮，数字随每次请求刷新，永远只显示当前轮
- **峰谷计价自动判定**：工作日高峰时段（北京时间 09:00–12:00 / 14:00–18:00）按峰价，其余时段及周六日全天按谷半价——与系统时区无关，纯事件时刻换算
- **模型分价**：V4 Flash / V4 Pro 单价不同，按每轮实际使用的模型计
- **仅 DeepSeek 官方 API 显示**：检测到非官方路由（第三方中转价格不同）时自动隐藏，宁可不算、不算错账
- **金额不截断**：小于 ¥0.01 时保留全部小数位——开局最便宜的时候一位都不丢

鼠标悬停读数可看明细：命中 token 数 × 单价 × 峰/谷标注 × 命中率 × 模型名。

## 安装

```sh
dsh plugin --profile web add meow-cachebilling
```

安装后重启 `dsh web` 即可，无需任何配置。

## 计价口径

| 项目 | 口径 |
|---|---|
| 缓存 | 本轮 cacheRead tokens × 命中单价 |
| 未命中 | （未命中输入 + 缓存写入）× 未命中单价 |
| 输出 | 输出 tokens × 输出单价 |
| 时段 | 工作日 09:00–12:00 / 14:00–18:00 为峰，其余（含周六日全天）为谷 |

内置价目表（元 / 百万 token，2026-08-17 官方刊例）：

| 模型 | 峰（命中/未命中/输出） | 谷 |
|---|---|---|
| deepseek-v4-flash | 0.1 / 3 / 9 | 0.05 / 1.5 / 4.5 |
| deepseek-v4-pro | 0.3 / 9 / 27 | 0.15 / 4.5 / 13.5 |

数据来源：`usage.cacheReadTokens`（DeepSeek API 的 `prompt_cache_hit_tokens`）。本插件是本地估算工具，实际扣费以 DeepSeek 账单为准。

## 说明

- 仅支持 DeepSeek 官方 API 计价；其他 provider 的路由不会显示读数。
- 未命中缓存的轮次会如实显示 ¥0——全新会话第一轮没有可复用的前缀，这是正常现象。
- 价格如有调整，可在源码 `src/index.ts` 的价目表中自行修改。
